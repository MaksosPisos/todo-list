# TodoList

SPA для заметок со списками задач, выполненное по тестовому заданию. У каждой заметки есть название и задачи с текстом и отметкой выполнения. Сохранённые заметки и черновики хранятся в браузере.

**Стек:** Nuxt 4, Vue 3 Composition API, TypeScript в строгом режиме, Pinia, SCSS, Vitest и Playwright. Компоненты интерфейса, модальные окна, история изменений и синхронизация с хранилищем реализованы самостоятельно.

## Запуск

### Docker

Из корня репозитория:

```sh
docker-compose up
```

Для Docker Compose v2:

```sh
docker compose up
```

Приложение доступно по адресу [http://localhost:3000](http://localhost:3000). При первом запуске образ собирается автоматически. Для пересборки после изменения исходников добавьте `--build`.

В репозитории есть [Dockerfile](Dockerfile) и [docker-compose.yaml](docker-compose.yaml). Сборка многоэтапная, на Node.js 24; приложение запускается под непривилегированным пользователем. Дополнительные сервисы, переменные окружения и тома не требуются: данные пользователя остаются в браузере.

### Локально

Нужны Node.js 24 версии от 24.15.0 и npm. Полный диапазон поддерживаемых версий указан в `engines` файла [package.json](package.json).

```sh
npm ci
npm run dev
```

Адрес приложения: [http://localhost:3000](http://localhost:3000).

Для сборки и локального просмотра production-версии:

```sh
npm run build
npm run preview
```

## Страницы и действия из ТЗ

В приложении два типа страниц: список заметок и редактор. Создание новой заметки использует тот же редактор.

| Страница       | Маршрут      | Возможности                                                                                                                                                    |
| -------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Список заметок | `/`          | Название, первые три задачи без возможности отмечать их, прогресс и количество скрытых задач. Создание заметки, открытие редактора, удаление с подтверждением. |
| Редактор       | `/notes/:id` | Изменение названия, добавление и удаление задач, редактирование текста и отметка выполнения. Сохранение, отмена редактирования и удаление, undo/redo.          |
| Создание       | `/notes/new` | Новая заметка в редакторе; до явного сохранения она существует только как черновик.                                                                            |

Сохранение возвращает к списку заметок. Отмена редактирования и удаление требуют подтверждения. При уходе с несохранёнными изменениями, в том числе при переключении заметок в боковой панели, появляется модальное окно: можно остаться или уйти без сохранения.

## История изменений

История реализована собственным журналом обратимых команд в [app/domain/history.ts](app/domain/history.ts). Управление сессией редактирования находится в [useNoteEditor.ts](app/composables/useNoteEditor.ts).

- Непрерывный ввод в одном поле объединяется в один шаг. Изменение фиксируется при потере фокуса, переходе к другому полю, структурном действии или паузе ввода 650 мс.
- Отметка чекбокса, добавление и удаление задачи создают отдельные атомарные шаги.
- Новое изменение после undo очищает ветку redo. Операции без фактического изменения данных не добавляются в историю.
- Лимит составляет 50 шагов. Для текста сохраняются старое и новое значения, для чекбокса - состояния, для добавления и удаления - одна задача и её позиция. Полные копии заметки для каждого шага не хранятся.
- История действует в рамках одной сессии. Успешное сохранение, подтверждённая отмена, удаление или выход её сбрасывают. Восстановленный черновик начинает новую историю.

Undo и redo доступны через кнопки и сочетания `Ctrl+Z` / `Ctrl+Shift+Z`; на macOS используется `Cmd`. Обработчик работает на всей странице редактора, включая текстовые поля, и перехватывает нативный undo, чтобы текст и структурные действия оставались в одной истории. Во время IME-ввода и при открытом модальном окне он не вмешивается.

## Хранение данных и черновики

Pinia хранит состояние приложения. Репозиторий [app/domain/storage.ts](app/domain/storage.ts) вручную читает и записывает данные; плагины автоматического сохранения стора не используются.

**Сохранённые заметки:** каждая запись находится в `localStorage` под ключом `quiet-notes:note:<id>` и содержит версию схемы `version: 1`. Изменения редактора не записываются в сохранённую заметку до нажатия «Сохранить заметку». Удаление также выполняется явно.

**Черновики:** хранятся отдельно в `sessionStorage` под ключом `quiet-notes:draft:<id>`, с версией схемы и исходной ревизией заметки. Запись выполняется после паузы 800 мс, а также при `pagehide`, `beforeunload` и скрытии вкладки. После случайной перезагрузки приложение предлагает восстановить или удалить черновик. Подтверждённая отмена и выход без сохранения удаляют его.

**Несколько вкладок:** событие `storage` обновляет список заметок. Перед сохранением проверяются наличие заметки и её `revision`, чтобы устаревшая вкладка не восстановила удалённую запись и не перезаписала новую версию.

### Обработка пограничных случаев

| Ситуация                                         | Поведение                                                                                                        |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| Прямой переход к несуществующей заметке          | Экран «Эта заметка не нашлась» со ссылкой на список.                                                             |
| Пустое название                                  | При сохранении используется «Без названия».                                                                      |
| Пустой текст задачи                              | Сохранение блокируется, появляется сообщение, фокус переходит к пустому полю. Заметку без задач сохранить можно. |
| Заметка удалена в другой вкладке                 | Редактор показывает уведомление и блокирует сохранение. Текст остаётся доступен для копирования.                 |
| В другой вкладке сохранена новая версия          | Появляется уведомление о конфликте, сохранение поверх новой версии блокируется.                                  |
| Хранилище недоступно или заполнено               | Появляется сообщение об ошибке; введённый текст остаётся в редакторе.                                            |
| Повреждённые данные или неизвестная версия схемы | Некорректные записи пропускаются с предупреждением, исходные данные не перезаписываются при загрузке.            |

Данные привязаны к браузеру и адресу приложения: другой домен или порт использует отдельное хранилище. Черновики переживают перезагрузку той же вкладки; восстановление после её закрытия не гарантируется. Проверка ревизий защищает от последовательных конфликтов; `localStorage` не обеспечивает транзакций для строго одновременной записи из нескольких вкладок.

## Интерфейс и доступность

- Собственная адаптивная вёрстка на SCSS, без UI-библиотек. Переиспользуемые элементы вынесены в `NoteCard`, `TodoRow`, `AppModal` и `AppIcon`.
- Модальные окна используют `<dialog>`: удерживают фокус, закрываются по `Escape`, поддерживают `Tab` / `Shift+Tab` и возвращают фокус к исходному элементу. Все подтверждения проходят через них, без `alert` и `confirm`.
- Карточка заметки открывается по всей площади. Удаление работает отдельно; текст можно выделить и скопировать. Доступны открытие через `Enter`, новая вкладка через `Ctrl` / `Cmd` + клик и видимый фокус.
- Поиск по названиям и текстам задач с debounce 300 мс; очистка поиска срабатывает сразу. Фильтры «Все», «В процессе» и «Завершённые» синхронизированы между панелью и списком через URL.
- Светлая и тёмная темы. До ручного выбора тема следует системной настройке; выбор сохраняется и синхронизируется между вкладками.
- Подписи полей, сообщения об ошибках, ссылка перехода к основному содержимому и поддержка `prefers-reduced-motion`.

Используются стандартные API браузера: `localStorage`, `sessionStorage`, `<dialog>` и `crypto.randomUUID()`. Для размещения вне localhost нужен HTTPS. Автоматические браузерные проверки настроены для Chromium; Firefox и Safari требуют отдельной проверки.

## Проверки

```sh
npm test
npm run typecheck
npm run format:check
npm run build
```

Vitest покрывает команды истории, лимит 50 шагов, ветвление undo/redo, группировку ввода, сохранение черновиков, работу стора и репозитория, валидацию схемы, ошибки хранилища и конфликты вкладок. Компонентные тесты по ТЗ не требуются.

Для E2E сначала запустите приложение через `npm run dev` или Docker. В другом терминале:

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright проверяет создание и редактирование заметок, клики по карточке, выделение текста, клавиатуру, модальные окна, восстановление после reload, несколько вкладок, поиск с debounce, фильтры, темы и мобильную вёрстку. Контексты браузера изолированы от обычного профиля пользователя. Скриншоты и трассировки неуспешных тестов сохраняются в `test-results/`.

Настройки E2E через переменные окружения:

| Переменная                            | Назначение                                                                  | По умолчанию            |
| ------------------------------------- | --------------------------------------------------------------------------- | ----------------------- |
| `PLAYWRIGHT_BASE_URL`                 | Адрес уже запущенного приложения                                            | `http://localhost:3000` |
| `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` | Абсолютный путь к установленному Chrome/Chromium вместо браузера Playwright | Браузер Playwright      |

В [GitHub Actions](.github/workflows/ci.yml) настроены установка зависимостей, проверка форматирования, unit-тесты, проверка типов и production-сборка. E2E запускаются отдельно.

## Структура проекта

```text
app/
  app.vue                      Общая оболочка и боковая панель
  pages/
    index.vue                  Список, поиск и фильтры
    notes/[id].vue             Редактор существующей или новой заметки
  components/                  Карточка, строка задачи, модальное окно, иконки
  composables/
    useNoteEditor.ts           Сессия, история, группировка ввода, черновики
    useConfirmation.ts         Подтверждения действий
    useNoteFilter.ts           Фильтр заметок через URL
    useTheme.ts                Переключение темы
  domain/
    notes.ts                   Типы, валидация и сравнение содержимого
    history.ts                 Обратимые команды и журнал на 50 шагов
    storage.ts                 Репозиторий и версионированные черновики
  stores/notes.ts              Состояние Pinia и явные операции с заметками
  plugins/                     Загрузка данных, синхронизация вкладок, тема
  assets/styles/main.scss      Стили, темы и адаптивная вёрстка
tests/
  unit/                        Vitest: история, редактор, стор и хранилище
  e2e/                         Playwright: заметки, навигация и темы
```
